# Клиент Shado: что делать и как

Спецификация под уже реализованный сервер (см. [README](../README.md)). Домен и
presentation приложения не меняются — при одном условии: **репозиторий продолжает
отдавать `Lesson.audioPath` как локальный путь к готовому к воспроизведению
файлу**, только теперь этот файл он при необходимости докачивает. Тогда плеер,
волна и все экраны остаются как есть.

Порядок работ — в конце документа (§11), там же чек-лист приёмки.

---

## 1. Общие правила API

- База: `http://127.0.0.1:8080` локально, `https://…` в проде. Все пути ниже —
  от корня, версия в пути: `/v1/...`.
- Тело запросов и ответов — JSON, `snake_case`, кодировка UTF-8.
- Времена — ISO-8601 UTC с миллисекундами: `2026-07-28T10:00:00.000Z`.
  В Dart: `DateTime.parse(...)` и `dt.toUtc().toIso8601String()`.
- Все длительности и позиции — миллисекунды, целые.
- Авторизация: `Authorization: Bearer <access_token>` на всех путях, кроме
  `/healthz` и `/v1/auth/*`.
- Идентификаторы — UUID v4 строкой. **UUID урока генерирует клиент** (как сейчас
  в `LessonRepositoryImpl`), UUID аудио — сервер.

### Формат ошибок

Один на весь API:

```json
{ "error": { "code": "validation_error", "message": "первый сегмент должен начинаться с 0" } }
```

| code | HTTP | Когда | Что делает клиент |
| --- | --- | --- | --- |
| `validation_error` | 422 | тело не прошло проверку (сегменты, email, пароль) | показать `message`, не повторять запрос |
| `invalid_credentials` | 401 | неверная пара email/пароль | «неверный email или пароль» |
| `email_taken` | 409 | email уже зарегистрирован | предложить войти |
| `unauthorized` | 401 | нет токена, токен истёк или refresh недействителен | см. §3, обновление токена или выход |
| `forbidden` | 403 | не хватает роли (админка) | скрыть раздел, не повторять |
| `not_found` | 404 | нет ресурса **или он чужой** | обработать как «удалён на сервере» |
| `version_conflict` | 409 | правка поверх устаревшей версии | см. §6, в `error.current` лежит актуальный урок |
| `payload_too_large` | 413 | файл больше лимита (50 МБ) | сообщить размер лимита до загрузки |
| `unsupported_media_type` | 415 | формат не поддержан или файл не читается | список форматов в сообщении |
| `rate_limited` | 429 | больше 10 попыток в минуту на `/v1/auth/*` | подождать минуту, показать таймер |
| `internal_error` | 500 | сбой сервера | «попробуйте позже», залогировать |

Правило на будущее: **неизвестный `code` — это не «всё хорошо»**. Мапить по
списку, всё остальное — общая ошибка по HTTP-статусу.

### Приватность данных

Аудио и уроки видны только их владельцу. Чужой ресурс отдаёт `404`, а не `403`, —
клиенту не нужно различать «нет» и «не твоё», в обоих случаях запись убирается
из локального кеша.

## 2. Что добавляется в приложении

| Слой | Что добавляется |
| --- | --- |
| `core/network` | `ApiClient` на `dio`: базовый URL, интерсепторы `Authorization`, refresh на 401, повтор при сетевых сбоях, единый разбор ошибок в `ApiException` |
| `core/storage` | `TokenStorage` поверх `flutter_secure_storage` (refresh-токен) + access в памяти |
| `features/auth` (новая) | `domain`: `AuthRepository`, use case'ы `login`/`register`/`logout`/`currentUser`; `data`: клиент API + хранилище токенов; `presentation`: экраны входа и регистрации |
| `data/datasources` | `LessonRemoteDataSource`, `AudioRemoteDataSource` (загрузка/скачивание), `RemoteWaveformDataSource` (пики) |
| `data/models` | отдельные DTO под API (`LessonDto`, `AudioDto`, `SegmentDto`). `LessonModel` оставить для sqflite: локально хранится путь к кешу, на сервере — `audio_id`, смешивать их в одной модели не стоит |
| `data/repositories` | `LessonRepositoryImpl`: сервер — источник истины, sqflite — кеш; докачивание аудио в `getLesson` |
| `core/router` | `redirect` по состоянию авторизации: без токена — на `/login` |
| Зависимости | `dio`, `flutter_secure_storage`, `crypto` (проверка sha256), `path_provider` (уже есть) |

Держать `LessonRemoteDataSource` и `AuthRepository` за интерфейсами, как сейчас
локальные источники, — тогда репозиторий и контроллеры тестируются на подделках
без сети.

## 3. Токены и сетевой слой

**Хранение.** Refresh — только в `flutter_secure_storage`, access — в памяти
(переживать перезапуск ему незачем, живёт 15 минут).

**Жизненный цикл.**

1. `register`/`login` → сохранить `refresh_token` в secure storage, `access_token`
   держать в поле `ApiClient`.
2. Старт приложения: refresh есть → сразу `POST /v1/auth/refresh`, получить
   access и данные пользователя; refresh нет или ответ 401 → экран входа.
3. Любой ответ 401 с `code: unauthorized` на обычном запросе → один параллельный
   запрос на refresh, остальные ждут его и повторяются.
4. 401 на самом refresh → полный выход: чистим secure storage, локальный кеш
   уроков и аудио, уводим на `/login`.

Пункт 4 обязателен: сервер гасит **всю цепочку** refresh-токенов, если пришёл уже
использованный (признак кражи). Тихо ретраить бессмысленно.

```dart
class AuthInterceptor extends Interceptor {
  AuthInterceptor(this._dio, this._tokens);

  final Dio _dio;
  final TokenStorage _tokens;
  Future<String?>? _refreshing; // один refresh на все параллельные запросы

  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) {
    final access = _tokens.access;
    if (access != null && options.extra['skipAuth'] != true) {
      options.headers['Authorization'] = 'Bearer $access';
    }
    handler.next(options);
  }

  @override
  Future<void> onError(DioException err, ErrorInterceptorHandler handler) async {
    final isAuthCall = err.requestOptions.path.startsWith('/v1/auth/');
    if (err.response?.statusCode != 401 || isAuthCall) return handler.next(err);

    final access = await (_refreshing ??= _refresh().whenComplete(() => _refreshing = null));
    if (access == null) return handler.next(err); // выход инициирует AuthRepository

    final options = err.requestOptions..headers['Authorization'] = 'Bearer $access';
    try {
      handler.resolve(await _dio.fetch(options));
    } on DioException catch (retryError) {
      handler.next(retryError);
    }
  }

  Future<String?> _refresh() async {
    final refresh = await _tokens.readRefresh();
    if (refresh == null) return null;
    try {
      final response = await _dio.post(
        '/v1/auth/refresh',
        data: {'refresh_token': refresh},
        options: Options(extra: {'skipAuth': true}),
      );
      await _tokens.save(response.data); // пишет новый refresh, обновляет access
      return response.data['access_token'] as String;
    } on DioException {
      await _tokens.clear();
      return null;
    }
  }
}
```

**Важно:** сервер ротирует refresh при каждом обновлении — новый `refresh_token`
из ответа надо сохранить, старый больше не работает.

## 4. Авторизация

| Метод | Путь | Запрос | Успех |
| --- | --- | --- | --- |
| POST | `/v1/auth/register` | `{email, password}` | `201 {user, access_token, refresh_token, expires_in}` |
| POST | `/v1/auth/login` | `{email, password}` | `200`, то же тело |
| POST | `/v1/auth/refresh` | `{refresh_token}` | `200`, новая пара |
| POST | `/v1/auth/logout` | `{refresh_token}` | `204` |
| GET | `/v1/me` | — | `200 {id, email, role, created_at}` |

```json
{
  "user": { "id": "e381…", "email": "user@example.com", "role": "user",
            "created_at": "2026-07-28T14:18:30.172Z" },
  "access_token": "eyJ0eXAi…",
  "refresh_token": "8f3a…",
  "expires_in": 900
}
```

Правила для UI:

- пароль — минимум 8 символов, проверять на клиенте до запроса;
- email нормализуется сервером (trim + lowercase), но лучше делать это и в поле
  ввода, чтобы «Вход» и «Регистрация» вели себя одинаково;
- ответ на «нет такого email» и «неверный пароль» одинаковый — показывать
  «Неверный email или пароль», не подсказывать, какие адреса зарегистрированы;
- `/v1/auth/*` ограничен 10 попытками в минуту на IP и на email: на `429`
  блокировать кнопку и показать, когда можно повторить;
- `logout` — послать `refresh_token`, затем локально почистить токены и кеш;
  ответ всегда `204`, ошибку игнорировать.

**Роли.** `user` и `owner`. Роль приходит в `user.role` и в `/v1/me`. Владелец
задан почтой на сервере (`arovitm@gmail.com`) — клиент роль не выбирает и не
запрашивает, только читает. Раздел админки (§8) показывать при `role == 'owner'`,
но не полагаться на это как на защиту: сервер всё равно проверяет.

## 5. Аудио

### 5.1 Загрузка идёт ДО создания урока

Экран «Добавить» сохраняет текущий порядок: выбрали файл → узнали длительность →
нарисовали волну с метками → «Создать урок». Первый шаг теперь делает сервер.

```http
POST /v1/audio
Authorization: Bearer <access>
Content-Type: multipart/form-data; boundary=…

поле: file (имя файла с расширением желательно)
```

Ответ `201` (или `200`, если такой файл уже загружался):

```json
{
  "id": "b21e…",
  "url": "http://127.0.0.1:8080/v1/audio/b21e…/file",
  "content_type": "audio/mpeg",
  "size_bytes": 2938471,
  "sha256": "3f2a…",
  "duration_ms": 183400,
  "peaks": { "resolution": 2000, "minima": "<base64 int8>", "maxima": "<base64 int8>" }
}
```

- **`duration_ms` считает сервер** — локальный замер через `just_audio`/libmpv
  (`AudioFileDataSource.resolveDurationMs`) на этом пути больше не нужен.
- Форматы: `mp3, m4a, aac, wav, flac, ogg`. Размер — до 50 МБ; проверять до
  отправки, чтобы не гонять зря трафик.
- `200` вместо `201` означает дедупликацию по `sha256`: та же запись, повторной
  обработки не было. Для клиента разницы нет.
- Загрузка длинного файла — секунды: показывать прогресс через `onSendProgress`
  и давать отмену (`CancelToken`).
- **Сразу после загрузки положить файл в кеш приложения** под ключ `audio_id`:
  он уже есть локально, качать его обратно после создания урока не нужно.

### 5.2 Пики отдаёт сервер

```http
GET /v1/audio/{id}/peaks?resolution=2000
→ { "resolution": 2000, "minima": "<base64>", "maxima": "<base64>" }
```

`resolution` в ответе — фактическое число точек. Сервер хранит огибающую в
высоком разрешении и прореживает под запрос; **повысить разрешение выше
сохранённого нельзя** — вернётся меньше точек, чем просили, это нормально,
рисовать надо по фактическому `resolution`.

Потолок — примерно 172 точки на секунду звука (внутренний блок 256 фреймов) и
4000 точек на файл. То есть для минутного и более длинного урока вы всегда
получите запрошенные 2000, а для десятисекундного отрывка — около 1700, и
виджет должен растягивать то, что пришло, а не ждать ровного числа.

Значения нормализованы так же, как сейчас на клиенте: `maxima` 0..1,
`minima` -1..0, пик прижат к единице.

```dart
List<double> decodePeaks(String encoded) {
  final bytes = base64Decode(encoded);
  final signed = bytes.buffer.asInt8List(bytes.offsetInBytes, bytes.lengthInBytes);
  return [for (final value in signed) value / 127.0];
}
```

В приложении это ровно одна новая реализация существующего интерфейса
`WaveformDataSource` — `RemoteWaveformDataSource`. Локальные реализации остаются
запасным путём для офлайна. Побочный эффект, ради которого всё и делалось: волна
выглядит одинаково на всех платформах, и на десктопе больше не нужен
`flutter_soloud`.

### 5.3 Файл: скачать один раз, играть локально

```http
GET /v1/audio/{id}/file
Authorization: Bearer <access>
→ 200, Accept-Ranges: bytes, ETag: "<sha256>", Cache-Control: private, immutable
```

**Играть по сети напрямую не нужно.** В shadowing куски зацикливаются по 2–3
секунды, и `ClippingAudioSource` поверх сетевого источника будет дёргаться на
каждом повторе. Правильный путь: при первом открытии урока файл скачивается один
раз в кеш приложения (туда же, где сейчас лежит аудио), а плеер как и сегодня
работает с `AudioSource.file`.

- Ссылка требует заголовок `Authorization` — отдать её напрямую плееру или
  `Image.network`-подобному виджету нельзя, качать через `dio.download`.
- Поддерживается `Range`: обрыв докачивается заголовком
  `Range: bytes=<уже скачано>-`, ответ `206` с `Content-Range`.
- Целостность проверять по `sha256` из ответа `POST /v1/audio` или из
  `lesson.audio.sha256`: не совпало — файл удалить и скачать заново.
- Имя в кеше — `audio_id` (+ расширение из `content_type`). Файл иммутабелен:
  содержимое под одним `audio_id` не меняется никогда, инвалидация не нужна.
- Чистка кеша — по LRU и при удалении уроков; **осторожно: один `audio_id` может
  быть у нескольких уроков** (дедупликация по `sha256`), удалять файл только
  когда на него не ссылается ни один живой урок.

## 6. Уроки

```json
{
  "id": "9f1c…",
  "title": "TED: How to learn",
  "duration_ms": 183400,
  "created_at": "2026-07-28T10:00:00.000Z",
  "updated_at": "2026-07-28T10:12:03.000Z",
  "deleted_at": null,
  "version": 3,
  "audio": { "id": "b21e…", "url": "…/v1/audio/b21e…/file", "content_type": "audio/mpeg",
             "size_bytes": 2938471, "sha256": "3f2a…", "duration_ms": 183400 },
  "segments": [
    { "index": 0, "text": "Hello there.", "start_ms": 0, "end_ms": 2100 },
    { "index": 1, "text": "How are you?", "start_ms": 2100, "end_ms": 4300 }
  ]
}
```

| Метод | Путь | Смысл |
| --- | --- | --- |
| GET | `/v1/lessons?since=&limit=&cursor=` | список, `updated_at desc` |
| GET | `/v1/lessons/{id}` | один урок, заголовок `ETag: "<version>"` |
| PUT | `/v1/lessons/{id}` | создать (`201`) или обновить (`200`) |
| DELETE | `/v1/lessons/{id}` | мягкое удаление, `204` |

### Создание урока

```http
PUT /v1/lessons/<uuid, сгенерированный клиентом>
Content-Type: application/json

{ "title": "TED: How to learn",
  "audio_id": "b21e…",
  "created_at": "2026-07-28T10:00:00.000Z",
  "segments": [ { "index": 0, "text": "…", "start_ms": 0, "end_ms": 2100 }, … ] }
```

`PUT`, а не `POST`, потому что UUID генерит клиент: повтор после потери сети не
создаёт дубль. `duration_ms` присылать не нужно — сервер берёт длительность
аудио; если прислать и не совпадёт, будет `422`.

**Инварианты, которые сервер проверяет** (те же, что в домене приложения, — не
дайте им разойтись):

- сегментов ≥ 1, `index` идут `0..N-1` без дыр;
- границы строго возрастают и идут встык: `segments[i].start_ms == segments[i-1].end_ms`;
- `segments[0].start_ms == 0`, `segments[N-1].end_ms == duration_ms` аудио;
- `audio_id` принадлежит тому же пользователю (иначе `404`).

Проверять это на клиенте до отправки: пользователь должен получать ошибку от
редактора меток, а не от сети.

### Правка урока

Тот же `PUT`, сегменты приходят **целиком** — это агрегат (ровно так же работает
`LessonLocalDataSource.upsertLesson` и use case `UpdateLessonContent`). При
обновлении обязателен заголовок:

```http
If-Match: "3"
```

Версию брать из `lesson.version` (или из `ETag` последнего `GET`). Без заголовка
или с устаревшей версией — `409 version_conflict`, актуальный урок лежит в
`error.current`:

```json
{ "error": { "code": "version_conflict", "message": "version conflict",
             "current": { "id": "9f1c…", "version": 4, "segments": [ … ] } } }
```

Для приложения на одного пользователя это редкость (два устройства правят один
урок). Достаточно: записать `current` в кеш, показать «урок изменён на другом
устройстве» и предложить повторить правку поверх свежей версии. Молча
перезаписывать чужую версию нельзя.

Обновление снимает мягкое удаление: `PUT` по удалённому уроку восстанавливает его.

### Удаление

`DELETE` — мягкое: урок остаётся с `deleted_at` и повышенной `version`, чтобы
удаление разошлось по устройствам. Локально запись убирать сразу. Повторный
`DELETE` того же урока — `204`, чужой или несуществующий — `404`.

## 7. Синхронизация и кеш

Схема намеренно простая, и её стоит держать простой, чтобы не скатиться в
offline-first раньше времени:

- **сервер — источник истины**, sqflite становится кешем для чтения;
- на старте и по pull-to-refresh: `GET /v1/lessons?since=<последний известный
  updated_at>` → применить дельту, записи с непустым `deleted_at` удалить из кеша
  вместе с осиротевшим аудио;
- **без `since`** список отдаёт только живые уроки; **с `since`** — дельту,
  включая удалённые. Это единственное различие, и оно важно: первый запуск делать
  без `since`;
- сохранять новый «водяной знак» — максимальный `updated_at` из полученных
  записей, а не текущее время устройства (часы могут врать);
- запись (создание, правка, удаление) идёт на сервер, при успехе — в кеш; нет
  сети — честная ошибка в UI, как сейчас при сбое БД;
- аудио кешируется по `audio_id`, чистка — по LRU и по удалённым урокам.

Пагинация: `limit` (по умолчанию 50, максимум 200) и `cursor` из `next_cursor`
предыдущего ответа. `next_cursor: null` — страниц больше нет. Курсор — строка
base64, при подстановке в query её нужно url-энкодить (`Uri.encodeQueryComponent`).

```json
{ "items": [ { … урок … } ], "next_cursor": "MjAyNi0wNy0yOFQxMDoxMjowMy4wMDBafDlmMWM…" }
```

Полноценная офлайн-очередь (`pending_operations`, разрешение конфликтов,
дозагрузка) — отдельный этап, и он нужен только если правка уроков без сети
действительно требуется. Швы для него уже есть: `version`/`If-Match` и мягкое
удаление.

## 8. Админка для owner

Показывать раздел только при `role == 'owner'`.

| Метод | Путь | Запрос → ответ |
| --- | --- | --- |
| GET | `/v1/admin/users?q=&limit=&offset=` | → `{users: [{id, email, role, created_at}], total, limit, offset}` |
| PATCH | `/v1/admin/users/{id}/role` | `{ "role": "user" \| "owner" }` → обновлённый пользователь |

- `q` — подстрока email, регистр не важен; `limit` до 200, `offset` для страниц.
- Роль в access-токене живёт до 15 минут, а сервер сверяет её с базой: только что
  повышенный пользователь получает доступ сразу, не дожидаясь нового токена.
- Понизить владельца, заданного в конфигурации сервера, нельзя — `422`. Кнопку
  «сделать user» для него лучше не показывать вовсе.
- Своя роль в `/v1/me` может измениться в любой момент: перечитывать её при
  входе в админку и прятать раздел на `403`.

## 9. Обработка ошибок в UI

Единый разбор в `ApiClient`: тело ошибки → `ApiException(code, message, status,
details)`. Дальше по слоям идёт `ApiException`, а не `DioException`.

- сетевые сбои (`DioExceptionType.connectionError/timeouts`) — «нет связи с
  сервером», кнопка «Повторить»; это не то же самое, что ошибка API;
- `unauthorized` обрабатывается интерсептором и наверх выходит только когда
  refresh не удался — тогда выход на `/login`;
- `not_found` при открытии урока — удалить из кеша и показать «урок удалён»;
- `version_conflict` — сценарий §6, не общий тост;
- `payload_too_large` / `unsupported_media_type` — проверять до отправки, но
  сообщение с сервера всё равно показывать (в нём причина);
- `rate_limited` — заблокировать форму входа на минуту.

## 10. Тестирование

- `LessonRemoteDataSource`, `AudioRemoteDataSource`, `AuthRepository` — за
  интерфейсами; репозиторий и контроллеры тестируются на подделках без сети.
- `dio` мокать через `DioAdapter`/`http_mock_adapter` — проверить: подстановку
  `Authorization`, единственный refresh на несколько параллельных 401, выход при
  401 на refresh, разбор всех кодов ошибок из §1.
- Отдельный тест на `decodePeaks`: base64 int8 → `-1..1`, длина равна
  `resolution` из ответа.
- Тест на конфликт: `PUT` без `If-Match` → 409 → в кеше оказывается `current`.
- Контрактные тесты сервера уже есть (`cargo test`, 26 штук) — при расхождении
  поведения сначала смотреть в них, они описывают ожидаемые статусы и тела.

## 11. Порядок работ

Каждый этап оставляет приложение в рабочем состоянии.

1. **Сеть и токены.** `ApiClient`, `TokenStorage`, интерсепторы, `ApiException`.
   Проверяется на `/healthz` и `/v1/me`.
2. **Авторизация.** Фича `auth`, экраны входа и регистрации, `redirect` в
   роутере, автологин по refresh на старте. Уроки на этом шаге ещё локальные.
3. **Аудио.** `POST /v1/audio` на экране создания (с прогрессом и отменой),
   `RemoteWaveformDataSource`, кеш файла по `audio_id`. Здесь же выравнивается
   поведение волны на всех платформах и убирается локальный замер длительности.
4. **Уроки.** `LessonRemoteDataSource`, сборка репозитория «сервер + кеш»,
   докачивание аудио при открытии урока, `If-Match` при правке.
5. **Дельта-синхронизация** по `since`, чистка кеша, pull-to-refresh.
6. **Админка** для `owner` (список пользователей, смена ролей).
7. **Потом, по необходимости:** офлайн-очередь записи, шаринг уроков, вход через
   Apple/Google (обязателен для iOS, если появится вход через соцсети).

### Чек-лист приёмки

- [ ] после перезапуска приложение входит само по refresh из secure storage;
- [ ] протухший access молча обновляется, пользователь ничего не замечает;
- [ ] refresh-токен после каждого обновления перезаписан новым;
- [ ] выход чистит токены, кеш уроков и аудиофайлы;
- [ ] загрузка 50 МБ показывает прогресс и отменяется;
- [ ] повторная загрузка того же файла не качает его второй раз (ответ `200`);
- [ ] волна рисуется по серверным пикам одинаково на Android, iOS, Windows;
- [ ] урок создаётся одним `PUT`, повтор при обрыве не создаёт дубль;
- [ ] правка с устаревшей версией показывает «изменён на другом устройстве»;
- [ ] удалённый на другом устройстве урок исчезает после pull-to-refresh;
- [ ] аудио играет из локального файла, зацикливание кусков не дёргается;
- [ ] раздел админки виден только owner и переживает `403` без падения.
