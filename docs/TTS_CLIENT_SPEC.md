# Озвучка через ИИ (Gemini TTS): что делать на клиенте

Дополнение к `CLIENT_SPEC.md`. Общие правила API (база, JSON snake_case, заголовок
`Authorization`, формат ошибок) — оттуда же, здесь только то, что нового.

## 1. Идея и место в UI

На экране создания урока рядом с загрузкой аудио появляется кнопка **«Озвучить
через ИИ»**. Пользователь вводит текст → жмёт кнопку → сервер синтезирует речь
через Gemini TTS и возвращает результат **в точности в той же форме, что и
загрузка `POST /v1/audio`** (ссылка на файл + волна). Дальше клиент работает с ним
как с обычной аудиодорожкой: тот же кеш, тот же плеер, то же создание урока с
`audio_id`.

- Кнопка видна только **авторам уроков** (`user-pro`, `admin`, `owner`) — там же,
  где доступна загрузка. У обычного `user` её нет; сервер ответит ему `403`.
- Для клиента загрузка файла и озвучка — два входа в один и тот же результат.
  Единственное отличие ответа — поле `cached` (см. §3).

## 2. Запрос

```http
POST /v1/tts/synthesize
Authorization: Bearer <access>
Content-Type: application/json

{ "text": "Nice to meet you. Let's get started." }
```

- `text` — обязательный. Модель, голос и стиль чтения задаёт **сервер**; клиент их
  не передаёт.
- Ограничения текста: не пустой, **≤ 2000 символов** и ≤ ~3800 байт UTF-8.
  Нарушение — `422 validation_error` ещё до обращения к провайдеру (лимит не
  тратится). Проверять длину до отправки.

## 3. Ответ

`200 OK`. Тело — как у `POST /v1/audio`, плюс `cached`:

```json
{
  "id": "b21e…",
  "url": "http://127.0.0.1:8080/v1/audio/b21e…/file",
  "content_type": "audio/wav",
  "size_bytes": 204844,
  "sha256": "3f2a…",
  "duration_ms": 4200,
  "peaks": { "resolution": 2000, "minima": "<base64 int8>", "maxima": "<base64 int8>" },
  "cached": false
}
```

- Формат аудио — `audio/wav` (PCM 24 кГц, 16 бит, моно): именно в таком виде
  отдаёт звук модель, и сервер не перекодирует его, чтобы не терять качество.
  Файлы соответственно крупнее mp3 (~48 КБ на секунду) — учитывать при кешировании
  на устройстве. `duration_ms` считает сервер, `peaks` декодируются так же, как в
  `CLIENT_SPEC.md §5.2`.
- **Файл отдаёт тот же эндпоинт** `GET /v1/audio/{id}/file` (с `Authorization`,
  `Range`, `ETag`, immutable) — см. `CLIENT_SPEC.md §5.3`. Отдельного пути для
  TTS-файла нет.
- Обращаться с результатом как с загрузкой: сразу положить файл в кеш под ключ
  `audio_id`, а `audio_id` затем передать в тело урока (`CLIENT_SPEC.md §6`).
- `cached` — синтез взят из серверного кеша (эта фраза уже озвучивалась). На
  поведение клиента не влияет; можно опционально показать «из кеша». Смысл поля —
  такой повтор **не тратит** бесплатный лимит.
- Аудио от ИИ обезличено и общее: один и тот же текст возвращает один и тот же
  `audio_id` разным авторам. Файл иммутабелен — инвалидация не нужна.

## 4. Ошибки

Формат общий (`CLIENT_SPEC.md §1`). Специфичные коды:

| code | HTTP | Когда | Что делает клиент |
| --- | --- | --- | --- |
| `validation_error` | 422 | пустой текст или длиннее лимита | показать `message`, не повторять |
| `forbidden` | 403 | роль `user` без прав автора | скрыть кнопку, не повторять |
| `unauthorized` | 401 | нет/протух токен | обычный путь refresh/выход (§3 CLIENT_SPEC) |
| `tts_quota_exceeded` | 429 | исчерпан бесплатный лимит озвучек (за минуту или за сутки) | показать `message`, **не ретраить**; предложить загрузить аудио вручную |
| `tts_unavailable` | 503 | сервис ИИ временно недоступен/не настроен | показать «попробуйте позже» + «Повторить» |

`tts_quota_exceeded` — не ошибка ввода: текст корректен, но бесплатный лимит
выбран. Лимитов два — на минуту и на сутки, поэтому отказ бывает временным
(«подождите минуту») и дневным. Кнопку не блокировать навсегда, но авто-ретраем не
долбить — предложить загрузить свой файл как запасной путь.

## 4.1 Остаток лимита

```http
GET /v1/tts/quota
Authorization: Bearer <access>
```

```json
{
  "provider": "gemini",
  "day":    { "used": 3, "limit": 14, "remaining": 11 },
  "minute": { "used": 0, "limit": 2,  "remaining": 2 },
  "month_chars": { "used": 812, "limit": 0 }
}
```

Права те же, что у синтеза (авторы уроков). `limit: 0` означает «без
ограничения» — тогда поле `remaining` не приходит вовсе. Полезно показать
`day.remaining` рядом с кнопкой: бесплатных озвучек в сутки немного, и увидеть
остаток заранее приятнее, чем упереться в отказ. Повторная озвучка уже
озвученной фразы берётся из кеша и лимит **не тратит**.

## 5. UX

- Синтез — сетевой вызов на несколько секунд (живая модель отвечает медленнее
  прежних голосов): показывать индикатор и давать **отмену** (`CancelToken`), как
  у загрузки.
- Один текст — один вызов. Не слать запрос на каждый символ ввода; синтезировать
  по явному нажатию кнопки.
- После успеха — тот же поток, что после загрузки: волна нарисована из `peaks`,
  файл уже в кеше, можно размечать сегменты и создавать урок.

## 6. Что НЕ входит

- **Тайминги сегментов сервер не отдаёт.** `/v1/tts/synthesize` возвращает один
  аудиофайл и его общую длительность, но не привязку слов/фраз ко времени.
  Разметка сегментов — по-прежнему на клиенте (как и для загруженного аудио).
- Выбор голоса/языка/скорости с клиента не управляется — это серверная настройка.

## 7. Чек-лист приёмки

- [ ] Кнопка «Озвучить через ИИ» видна авторам, скрыта у `user`.
- [ ] Пустой/слишком длинный текст ловится на клиенте до отправки.
- [ ] Успешный ответ обрабатывается идентично `POST /v1/audio`: кеш по `audio_id`,
      волна по `peaks`, дальше — создание урока.
- [ ] Файл играется через `GET /v1/audio/{id}/file` (скачать один раз в кеш).
- [ ] `tts_quota_exceeded` (429) и `tts_unavailable` (503) показывают понятное
      сообщение и не уходят в авто-ретрай.
- [ ] Остаток суточных озвучек (`GET /v1/tts/quota`) виден рядом с кнопкой.
- [ ] Долгий синтез можно отменить.
